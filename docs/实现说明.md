# 实现说明 — #1490 Bot 会话隔离

## 需求还原

企业知识库与多 Agent 协作系统（系列 50 单）的拆单之一。本单范围：
**为不同 Bot 和用户隔离会话上下文与历史记录**。

验收标准只有一句：**两个 Bot 的交叉访问测试不返回对方记录**——即
隔离是**实证性**要求，必须能跑出「读不到」的测试。

## 设计

### 1. 命名空间模型

```
命名空间 = bot_id :: user_id
存储结构 = store[bot][user][kind][session_id] -> record
kind     = context（近期会话上下文）| history（长期历史）
```

双维度隔离：改 bot 或改 user 任一维度，就是另一个命名空间。

### 1b. 两种运行模式

| 模式 | 构造 | 行为 |
|---|---|---|
| **绑定身份模式** | `SessionIsolator(identity=("hr-bot","u-101"))` | `write()` 校验写入目标必须等于本身份；越权写真实抛 `IsolationViolation` |
| **底层原语模式** | `SessionIsolator()` | 不鉴权，可写任意命名空间；身份校验由上层（如路由层）保证 |

设计取舍：隔离层本身不假设调用方来源，原语模式保持最小职责与
最大复用；需要就地强制的场景用绑定身份模式。测试 9/9b 分别
实测两种模式。

### 2. 三个安全接口

| 接口 | 行为 |
|---|---|
| `write(bot, user, kind, payload)` | 绑定身份模式下校验写入目标归属；越权写抛 `IsolationViolation`（测试 9） |
| `read(bot, user, kind)` | 只读指定命名空间（内部原语） |
| `read_with_guard(requester, ..., target, ...)` | **对外唯一读入口**：请求方≠目标 → 返回 `[]` + 审计，不抛错 |

关键设计决策：**越权读静默返回空、越权写硬拒绝**。
理由：读侧如果抛错，等于告诉调用方「这里有数据但你无权」，
形成侧信道；返回空 + 审计既保护数据又不泄露存在性。
写侧必须硬拒，否则数据会被污染。

### 3. 审计

每次被阻的交叉访问记一条：

```json
{"type": "cross_namespace_read_blocked",
 "requester": "hr-bot::u-101", "target": "finance-bot::u-202",
 "returned": 0}
```

`cross_access_check(observer, victim)` 返回 `(泄露数, 受害者总数)`，
供验收测试断言 `leaked == 0`。

### 4. 持久化

`save(path)` / `SessionIsolator(path)` 全程 JSON，隔离结构原样保留，
reload 后交叉访问仍为 0（测试 10 证明）。

### 5. 零依赖

纯标准库（json/os/sys/time/uuid），与系列 02 单（#1489）同风格，
买家无需安装任何东西即可复核。

## 与系列其他单的关系

- 02 角色卡（#1489）：定义 bot 的身份、职责、权限边界；
- **03 会话隔离（本单）**：把「边界」落实到运行时数据层面——
  角色卡说不能跨域，隔离层保证跨 bot 读不到记录；
- 05 协作路由（#1492）：多 bot 之间如何路由任务——路由是转交，
  不改变隔离边界，转交后仍是各 bot 读各 bot 的会话。
